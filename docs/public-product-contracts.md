# Public product contracts

This public product candidate runs independently with synthetic data. It is non-canonical, is not a release, and requires governance review before merging. It retains Apache-2.0 and the existing public dependency notices.

Customer authority comes from a unique stable customer ID with trustworthy original binding. Names, legacy matches, unresolved status, probable matches and R text cannot create an identity. Original observations and legacy provenance remain readable without silently rewriting stored rows.

R observations are scoped to reliable customer identity and product. An observed R value lacks operational authority without field approval. R remains independent of ABCD sales grading; observations for one product do not authorize another product.

Hospital navigation requires a stable hospital ID. Same-name hospitals remain distinct. The current route owns restoration: returning to Task and reloading must keep Task current, regardless of an older cached Hospital entry. Reloading a genuinely current Hospital route restores its exact ID and valid source context. If source context is unavailable, the explicit Hospital ID may reopen from the directory without inventing a Task or Activity origin. Hospital maintenance invalidates the directory cache.

Task remains the execution layer. Context navigation, Activity lifecycle and draft recovery retain their existing contracts. Customer navigation with unresolved evidence falls back to discovery instead of choosing a name match.

Fiscal years run October through September. October through December use calendar year FY-1 before selecting the previous month. Missing previous months remain null. Actual zero, hospital/product boundaries, denominator policy and unrelated reporting fields remain distinct and unchanged.

Public tests cover synthetic contracts and browser flows, including actual save, Back, reload and browser process restart. The unsigned Android build and JVM tests do not establish OEM, SAF, signing, updater or production-distribution parity. See [declared public variants](public-product-variants.md).
